## 二、`/memory-profile list` 警告的语义

用户看到：`Warning: No memory profile configured. Use /memory-profile add <name> <repoUrl>`

- 出处：`index.ts:711-715`，`list` 子命令在 `profiles` 为空时的提示
- **不是错误**：表示还没定义任何档案，插件走"顶层单仓库模式"（`memoryDir.repoUrl` + `localPath`），记忆功能完全正常
- 只有 `list` 会给这个提示；`/memory-profile`（不带参数）显示状态，会写 `(none - using top-level repoUrl/localPath)` 并列出仓库链接
- 当时用户配置：`profile`/`profiles` 均为空、`repoUrl=https://github.com/JianpChen/pi-memory-md.git`、`localPath=C:/Users/23932/.pi/memory-md`、状态文件不存在 → 警告符合预期，可无视

## 三、发现：活动档案已切到 work（空仓库）

写记忆时发现配置已经变了（用户已用上新功能）：

| 项 | 值 |
|---|---|
| `settings.json` 的 `profiles` | `work` → `pi-memory-2.git`；`personal` → `pi-memory-md.git` |
| `profile` / 状态文件 | `work`（状态文件 `~/.pi/agent/memory-md-profile`） |
| `~/.pi/memory-md-work` | pi-memory-2.git 的**空克隆**（0 个文件、无提交）→ 当时注入 **0 个文件**，等于“没有记忆” |
| `~/.pi/memory-md` / `~/.pi/memory-md-personal` | 都是 pi-memory-md.git，历史内容（研究类记忆）在这里 |

处理方式：本轮内容**两边都写** ——

1. 先写入旧目录 `~/.pi/memory-md`（默认/legacy 路径，历史完整）
2. 再把本轮这 5 个文件同步到**活动档案目录** `~/.pi/memory-md-work`，让记忆立刻生效（该仓库无提交，首次 push 会创建 main 分支）

实测确认：`git clone` 空仓库后 `git add + commit + git push` 可以正常创建远程分支（不会因无 upstream 而失败）。

> 待用户抉择：是把 pi-memory-md.git 的内容整体迁移到 `work`，还是直接 `/memory-profile use personal` 用回旧仓库。
> 在此之前，“切到 work 就等于没有记忆”。
