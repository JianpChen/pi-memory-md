# 离线检索原理（可复用的算法方案）

解决「记忆检索要联网下载 embedding 模型」的问题，**纯算法替代向量检索，零模型下载**。
最初实现在 `pi-memory-agent`，思路可迁移到任何需要离线语义检索的场景。

## 三种模式

| 模式 | 算法 | 用途 |
|---|---|---|
| `keyword` | **BM25** | 精确关键词命中 |
| `semantic` | **汉字字符 n-gram Jaccard 相似度** | 模糊/近义命中 |
| `deep` | 两者各自归一化后**各 0.5 加权** | 综合排序（默认） |

## 处理流程
1. **收集文档**：`MEMORY.md` / `SCRATCHPAD.md` / `daily/*.md`，按**空行切块**，每块 ≤2000 字符
2. **分词**：汉字 bigram / 单字、`#tag`、`[[双链]]`
3. **打分**：按所选模式计算
4. **排序截断**返回

## 关键认识
- 不用向量 embedding（需下载模型、需联网），改用**纯数学计算**即可获得可用的模糊召回
- 汉字按 **字符 n-gram** 切分能绕开分词器依赖，且对中文短查询鲁棒
- 两路打分**各自归一化后再加权**，避免量纲不同导致某一路压倒另一路

## 后续演进（pi-memory-md）
新插件改用了 `@orama/orama` 做 BM25，中文分词用 `nodejieba`，
但同样是**动态加载 + 失败兜底**：`import("nodejieba").then(...).catch(() => null)`，
加载失败就回退 `fallbackChineseTokens`（按汉字连续段切分）。**离线可用的思路一脉相承。**
